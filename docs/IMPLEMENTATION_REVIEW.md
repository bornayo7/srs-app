# Implementation review and historical finding reconciliation

The overhaul replaces unsafe orchestration while retaining the existing local-first study model and pure grading, queue, gating and ladder engines. This document reconciles the historical audit inventory to the implemented boundaries and their evidence. It is not a claim that the inventory contained 65 independent, newly reproduced defects, or that every browser/provider combination has passed.

The baseline is `42c55fc`. [AUDIT_INVENTORY.md](AUDIT_INVENTORY.md) preserves the original labels and their corrections; [CODEBASE_REVIEW.md](CODEBASE_REVIEW.md) records the initial full-read review; [OVERHAUL_PLAN.md](OVERHAUL_PLAN.md) records the proposed execution. The final revision, aggregate checks and browser acceptance ledger belong in [IMPLEMENTATION_PROGRESS.md](IMPLEMENTATION_PROGRESS.md). Installation, supported formats, recovery and remaining manual qualification are in [RECOVERY_AND_RELEASE.md](RECOVERY_AND_RELEASE.md).

## Maintainability outcome

The important change is ownership of invariants. Components no longer have to know which card tables to update, when to settle unlocks, or how to preserve a plan while network work is pending. Small interfaces now own those consequences together:

| Boundary | Interface and responsibility | Implementation |
|---|---|---|
| Authored content | `validateItemContent(values, type)` / `assertItemContent` validate the same field shapes and answerability for editor, packet, migration and study preparation. Type validation owns identity, names and supported modes. | `src/engine/contentValidation.ts`, `src/engine/typeDesign.ts` |
| Revisioned study | A prepared question carries Card, Item and ItemType lifetime/revision observations. Commits compare them transactionally; undo advances revisions and refuses stale authority. | `src/services/studyRevision.ts`, `commitReview.ts`, `undo.ts`, `manualSrs.ts`, `src/engine/revision.ts` |
| Prepared questions | `prepareQuestions` returns usable entries and explicit repair problems. Grading and keyboard assistance are independent of React and shared across review, lesson and practice. | `src/services/questions.ts`, `src/engine/question.ts` |
| Content commands | `createCourseWithType`, `convertCapture`, `saveCourseSettings`, `saveItemEdit` and `saveItemTypeEdit` express complete user intentions with validation, derived state and ownership cleanup. | `src/services/contentCommands.ts`, `itemTypes.ts`, `src/db/repo/items.ts` |
| Authoring draft | `useFieldDraft` owns parsed values, invalid raw cloze, field errors, pending attachments and captured type identity. A completion from another draft cannot patch the current one. | `src/components/editor/useFieldDraft.ts`, `FieldValueInput.tsx` |
| Plans and candidates | Unit commands patch current state. Network generation produces candidates; current target assumptions are checked before proposals and the generation marker commit together. Acceptance resolves live dependencies. | `src/services/plans.ts`, `proposals.ts`, `src/ai/generateUnit.ts` |
| Persistence and interchange | Backup decoding validates the full graph; replacement is atomic and protects device configuration. Packet parsing is shared with MCP; receipts distinguish import from archive cleanup. | `src/db/backupSchema.ts`, `backupCodec.ts`, `import.ts`, `src/packages/`, `src/exchange/`, `srs-mcp/exchangeFiles.ts` |
| Provider transport | The actual schema crosses the wire; bounded correction, explicit refusal/truncation/empty handling and parameter-specific negotiation stay outside editors. | `src/ai/client.ts`, `transport.ts`, `config.ts` |

This is a set of deeper domain modules, not a generic configurable session framework. Review, lesson teaching and cram retain their different lifecycles. Native browser transports replace the bundled provider SDKs. The Node adapter and browser adapter share the packet contract; neither embeds a second item schema.

The baseline Course page was 845 lines; it is 165 lines at this review. Its items/search, addition, progress and settings live in `src/components/course/`. The Plan page fell from 762 to 311 lines: unit/date presentation remains local, while candidate queues and editing are shared in `src/components/proposals/`. The type designer fell from 569 to 92 lines, with the migration dialog and template editor separated by responsibility. The largest production TypeScript/TSX/CSS file under `src/` and `srs-mcp/` is `src/packages/importPacket.ts` at 489 lines. No production source file in that scope exceeds 1,000 lines. These are measured physical line counts, including blank lines, rather than a substitute for reviewing responsibility boundaries.

The importer still contains several packet-kind branches because it owns the atomic mutation outcome of those kinds. It is a reasonable next extraction candidate if new formats add policy. Current splitting removed duplicated content resolution and blob validation rather than moving each branch into a one-function file. Components still use ordinary React state where it remains local; the shared draft owner is reserved for state that must remain coherent across asynchronous operations.

## Design result and limits of the evidence

The workspace uses dark ink-teal surfaces (`#102228`, `#173038`), quiet slate structure and mint-teal action/focus color. A persisted light option uses pale paper (`#f5f8fa`) and dark ink (`#153747`). Study text has a separate Japanese-capable font stack and generous line height. The implemented platform stack uses Bahnschrift/Aptos for controls and Yu Gothic/Hiragino/Noto Sans JP for learning content; the proposed downloaded fonts were not added, so there is no new font network dependency.

The hierarchy is intentionally task-based: Today → course → Study / Items / Plan & drafts / Course settings. Primary actions and summaries wrap; the course section strip owns its horizontal scrolling. Item search/status filtering and 50-row expansion reduce page weight without hiding stored content. Native dialogs provide focus entry/return; fields and icon actions have accessible names, feedback has alert/status roles, focus outlines are visible, and reduced-motion preference is respected. Repair links return to the relevant item instead of losing study context.

Chromium-shell checks established no page overflow at 320px on dashboard/course/editor, a contained plan at 375px, and settings at 768px. Native dialog focus entry/return, invalid-content recovery, lesson wrong→retry→completion, review→undo, wrap-up and a real two-tab stale commit were exercised. Production offline reload and legacy Anki parsing/import were exercised after shutting down the server. These observations supplement the automated cases; they do not establish Safari/Firefox/Edge, installed-PWA update behavior, screen-reader coverage, native folder permissions, real system Japanese IME, or paid-provider/model compatibility.

The design remains a study utility with dense configuration available on its settings screen. It uses platform typography and restrained decoration rather than custom art. That supports offline use and Japanese legibility, but produces different glyph metrics across operating systems; long content and native controls still need platform-specific acceptance. Shared Tailwind color-token overrides retain old color-name identifiers in existing components; a future semantic-token pass could make those names more literal, but adding another styling abstraction was not necessary for this overhaul.

## Preserved scope and recovery policy

- Local-first learning, custom fields/templates/ladders, dependencies and levels, sticky passes, typed/kana/choice/sentence-cloze study, ghosts, manual controls, cram, notes/answer exceptions, captures, packages, Anki and assistant proposals remain in scope. Supported course packages preserve content/authoring/release behavior; personal progress belongs in a full backup.
- Reset/suspend continuing to leave existing ghost drills alive is an explicitly preserved product policy. Scheduled MCP, attaching plans to existing courses, unit reordering and AI-written distractors remain separate deferred features.
- Self grading, plain-cloze grading, FSRS and reveal-style study remain unsupported and are rejected with an explanation instead of being represented as working features.
- Date-only releases retain midnight UTC. Local daily allowance and forecast use calendar-day boundaries. Short stage delays through one hour remain exact; longer stages retain hour alignment.
- Each restore assigns new lifetime identities and invalidates historical undo authority. Numeric revisions alone cannot distinguish a replaced dataset. Database migration and backup validation do not make an older build safe to run against the new schema; use the documented backup/profile recovery procedure.

No remaining high-conviction material defect was identified in the scoped implementation/source reviews after their reported corrections. That is a bounded review outcome. The acceptance ledger and recovery guide retain the unverified environments and deliberate product exclusions instead of treating “all checks passed” as a guarantee of perfect behavior.
